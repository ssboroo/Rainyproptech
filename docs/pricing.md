# RAINY VISTA — 200% markup, үнэ ба кредит

Шалгасан: 2026-10-15. Хувилбар: 2026-10-15.3. Нэг кредит = **100₮**. Доорх нь төлөвлөсөн борлуулах үнэ; бодит Fal нэхэмжлэхтэй тулгах шаардлагатай.

## Өртөг ба ашгийн арга

- Монголбанкны 2026-10-14-ний ханш 3,595.99₮/USD. Борлуулалтын тооцоонд **3,700₮/USD** хэрэглэнэ: банкны хөрвүүлэлт ба ханшийн хэлбэлзлийн ~2.89% нөөц. Энэ нь live банкны ханш биш.
- API өртгийн **5% нөөц**: төлбөртэй алдаа, дахин боловсруулах эрсдэлийн төсөв; бодит failure rate гэж батлаагүй.
- Төлбөр хүлээн авах **3% шимтгэлийн таамаг**. Бодит банк/checkout гэрээгээр солих; тогтмол гүйлгээний хураамж ороогүй.
- Үүсгэлт бүрт **50₮ ажиллагааны нөөц**. Жишээ нь 100,000₮/сар / 2,000 үүсгэлт. Энэ нь Railway/Supabase-ийн батлагдсан нэхэмжлэх биш. Хэрэглээ бага бол уг нөөцийг өсгөх эсвэл тусдаа платформын сарын төлбөр шаардлагатай.
- **200% markup = өртөг × 3**, 200% profit margin биш. Шимтгэлгүй суурь орлогын margin ~66.67%. НӨАТ, орлогын татвар, маркетинг, цалин тооцоонд ороогүй; 200% цэвэр ашиг баталгаалахгүй.

```
C = API ($) × 3,700 × 1.05 + 50₮
Кредит = ceil(C × 3 ÷ 0.97 ÷ 100₮)
Үнэ = Кредит × 100₮
Төлөвлөсөн үлдэх ашиг = Үнэ × 0.97 − C
```

Дээш тоймлолт, төлбөрийн шимтгэлийг нөхсөн томьёо нь дээрх нөөцтэй өртгийн дараа хамгийн багадаа 200% markup хадгална. API $0.56 нь хэрэглэгчийн эцсийн үнэ биш.

## Видео тохиргоо ба шалгалт

- Видеоны уртыг загварын schema-д дэмжигдсэн секундээр сонгоно. Kling 3 Pro / O3 / Native 4K нь 3–15 секунд; бусад загварын бодит хүрээ өөр.
- Нягтаршлын сонголт яг тухайн endpoint-ийн дэмжлэгтэй. Автомат горимд 4K сонгоход native 4K endpoint рүү шилжинэ. 1080p endpoint-д 4K гэж шошго зүүхгүй.
- Дуугүй видео. Дуу, voice control нэмэхэд тусдаа үнэ баталгаажуулах шаардлагатай.
- Кадрын харьцаа эх зургаас хамаарна. MP4-ийн MB хэмжээг урьдчилан батлахгүй; encoder ба хөдөлгөөнөөс хамаарна.
- Видеоны **урт** ба **боловсруулах хугацаа** өөр. API queue/model-оос хамаарч хэдэн минут шаардаж болно; бүх загварт нэг ETA амлахгүй.
- `docs/model-audit.json`: одоогийн 100 endpoint-ийг албан ёсны Fal API/OpenAPI-тай тулгасан. 100 таарсан, 0 schema өөрчлөлт, 0 татаж чадаагүй. Энэ нь төлбөртэй inference/чанарын benchmark биш.
- `tests/video-options.test.ts`: 50 видео adapter-ийн 1,000-аас олон хугацаа/нягтаршлын хослолд input schema шалгаж, үнэтэй хослол бүрийг тооцно.
- **51 загвар** урьдчилан тооцох үнийн дүрэмтэй. **100 загварын** нийтэлсэн тарифыг `lib/model-tariffs.json`-д эх сурвалжтай хадгалж UI-д харуулна. **49 загвар** токен/GPU/пиксел/оролтын хэмжээг найдвартай хэмжих adapter шаардлагатай тул урьдчилсан суутгал нээгдтэл идэвхгүй. Тэдгээрт зохиомол тогтмол үнэ тавиагүй.
- Nano Banana Pro: чанарт чиглэсэн 4K рендер. Seedream 5 Pro: 2048² интерьер. Kling 3 Pro / O3: архитектурын зөөлөн хөдөлгөөн. Kling Native 4K: премиум өндөр нягтаршил. Эдгээр нь бүтээгдэхүүний сонголт; өөрийн эх зургаар төлбөртэй A/B benchmark хийх хүртэл “бүгдээс хамгийн сайн” гэж батлахгүй.

## Суутгал, буцаалт, хамгаалалт

1. `/api/pricing` нь сонгосон adapter-ийн нэг зураг, эсвэл тодорхой секундын видеоны үнийг харуулна. Зураг 4K/2K, видео хугацаа болон дуугүй тохиргоо үнийн тооцоотой ижил.
2. Үүсгэхэд сервер үнээ дахин тооцно. Клиентийн `expected_credits` ба `pricing_version` зөрвөл шинэ үнийг харахыг шаардаж **кредит суутгахгүй**.
3. Supabase transaction баланс түгжиж, нэг UUID-д нэг удаа үнийн дүнгээр суутгана. Үнийн snapshot тухайн generation дээр хадгалагдана. Browser-оос баланс, үнийн snapshot бичих эрхгүй.
4. Баталгаатай бүтэлгүй generation нэг удаа бүтэн кредит буцаана. Provider-д хүрсэн эсэх нь тодорхойгүй timeout бол давхар хүсэлт явуулахгүй; reconciliation шаардлагатай.
5. Шинэ үнэ хуучин дууссан ажлын суутгал/буцаалтыг өөрчлөхгүй. Шинэ систем эхлэх үед production дээр 0 данс, 0 generation байсан тул хуучин үлдэгдлийг хөрвүүлээгүй.

## Монгол орчин ба төвлөрсөн Fal төлбөр

- Видео нь parent рендерийн хадгалсан орчин, улирлыг өвлөнө; үйлчлүүлэгчийн илгээсэн өөр байршлаар дахин нүүлгэхгүй. Хуучин metadata-гүй рендер эх орчноо хадгална.
- Хэрэглэгч Supabase дахь өөрийн дотоод кредитээс суутгуулна. `FAL_KEY` зөвхөн сервер дээр байна. Бүх үүсгэх/төлөв шалгах/үр дүн авах хүсэлт энэ төвлөрсөн түлхүүрээр хийгдэнэ. Fal өөрийн тарифаар **тухайн түлхүүрийн эзэмшигчийн Fal balance**-аас бодит хэрэглээг тооцно. Дотоод нэг кредит Fal-ийн нэг доллартай адил биш.
- Сайтад кредит зарах нь Fal үлдэгдлийг автоматаар цэнэглэхгүй. Эзэмшигч Fal дээр хангалттай үлдэгдэлтэй байх шаардлагатай. Платформ хэрэглэгчээс хувийн Fal түлхүүр авахгүй.
- `GET /api/models` зөвхөн төвлөрсөн холболт тохируулагдсан эсэх boolean буцаана. Түлхүүр, Fal дансны долларын үлдэгдлийг нийтэд гаргахгүй.
- Starter 50,000₮; Studio 150,000₮; Business 500,000₮. Онлайн төлбөрийн gateway холбогдоогүй тул хэрэглэгч худалдан авсан мэт харагдуулахгүй; админ төлбөр баталгаажуулж цэнэглэнэ.

## Архитектурын админ ба Wire.mn (2026-10-15)

- Хэрэглэгчийн `/api/pricing` болон `/api/models` хариу зөвхөн `RetailQuote` (нийт ₮, кредит, model/output, version) өгнө. API $, ханш, markup, нөөц, эх сурвалжийн тариф нь зөвхөн `/api/admin/*` дээр байна.
- Хөтчийн компонентууд `lib/pricing.ts`-ийг runtime-аар импортлохгүй. Generations хүснэгтийн `price_quote` баганы SELECT эрх authenticated-д олгоогүй.
- Админ: `/admin`. Supabase `getUser(token)`-оор баталгаажсан, email_confirmed_at-тай, серверийн `ADMIN_EMAILS` allowlist эсвэл app_metadata.role=admin эрхтэй хэрэглэгч. User metadata ашиглахгүй. Production owner allowlist: ssboroostore@gmail.com; эхлээд өөрийн имэйлээр бүртгэлээ баталгаажуулна.
- Админ ханш/шимтгэл/нөөц/нэг ажлын зардал, тарифын review огноо, автомат загвар, per-model тарифын matrix, нээлттэй/хаалттай төлөвийг удирдана. Markup 200% буюу cost basis ×3 хэвээр. Revision нь үнийн snapshot-д орно, хуучирсан quote-оор суутгахгүй. CAS шинэчлэлт + audit log.
- Wire adapter нь `ssboroo/socialtool-store/src/lib/wire.ts` урсгалд суурилсан, одоогийн https://docs.wire.mn/docs/quickstart JSON API-д нийцүүлсэн. Өмнөх project-ийн webhook-ийг өөрчлөхгүй.
- `SETTINGS_ENCRYPTION_KEY`: 32 random байт, base64, зөвхөн серверийн environment. Түлхүүрийг солихоос өмнө шифрлэсэн secrets-ийг шилжүүлэх шаардлагатай. Wire API key/signing secret AES-256-GCM-аар шифрлэгдэнэ. Admin GET нууцыг буцаадаггүй, зөвхөн configured boolean.
- Хуучин Wire түлхүүрийн утга Railway OAuth-д redacted тул автоматаар хуулж чадаагүй. Эзэмшигч өмнөх live key-гээ `/admin` → Wire.mn холболт хэсэгт нэг удаа оруулна. Хэрэглэгчээс API түлхүүр авахгүй. Live key байгаа, paymentsEnabled үед checkout нээгдэнэ.
- `POST /api/payments/create`: нэвтэрсэн эзэмшигч, UUID, зөвхөн pack нэр хүлээн авна. Дүн/кредит серверийн тогтмол pack-аас. Wire-д бүхэл төгрөгөөр явуулна (×100 биш). Stable idempotency key, intent-ийг checkout-оос өмнө хадгална. Checkout URL зөвхөн HTTPS pay.wire.mn. Client secret буцаахгүй.
- `/api/payments/status` нь зөвхөн өөрийн захиалгыг уншиж, Wire API-аас intent-ийг дахин шалгана. Webhook нь raw body HMAC-SHA256 + 5 минутын replay window шалгаад Wire API-аар давхар баталгаажуулна.
- `settle_credit_order`: order row lock, exact intent/amount/MNT шалгалт, unique intent/order ledger, нэг transaction-д paid + баланс нэмэх. Redirect эсвэл client status кредит нэмэхгүй. Replay/concurrent delivery нэг удаа биелнэ.
- Shared project ашиглаж webhook нэмэх боломжгүй бол verified polling ажиллана: цэнэглэлтийн дэлгэц дээр 8 секунд тутам, харагдах үед, хамгийн ихдээ 15 минут; дараа нь гараар шалгана. Шинэ webhook endpoint ашиглах бол `/api/payments/webhook`, event `payment_intent.succeeded`.
- Кредит борлуулалтын орлого Fal дансыг автоматаар цэнэглэхгүй. Fal billing тусдаа; `FAL_KEY` төвлөрсөн хэвээр.
